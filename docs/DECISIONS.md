# Architecture Decision Log

Short ADR-style entries. Each records **what** was decided and **why**, in one or two lines.
Newest entries are appended at the bottom.

| #   | Decision | Reason |
| --- | -------- | ------ |
| 001 | Project name **Linkpulse**. | A short, memorable name for the repo, UI and docs. |
| 002 | Pinned `requirements.txt` / `requirements-dev.txt`; `pyproject.toml` holds tool config only. | Deterministic installs and simple Docker layer caching without requiring Poetry/uv. |
| 003 | SQLAlchemy **2.1.x** (the current 2.x release) using the 2.0-style typed API. | The spec asks for the SQLAlchemy 2.0 API; 2.1 is that same API with fixes. |
| 004 | The full data model (users, links, clicks) ships in the **initial Alembic migration** in Phase 1. | The schema is fully specified up front; one coherent baseline beats three tiny migrations. Every later change is a new migration. |
| 005 | `BIGINT GENERATED BY DEFAULT AS IDENTITY` primary keys, not UUIDs. | Smaller and faster indexes. Ownership is enforced in every query, so guessable IDs leak nothing. |
| 006 | Composite index `clicks(link_id, clicked_at)` replaces a standalone `link_id` index. | Its leftmost prefix serves `link_id` lookups, so a second index would only slow the worker's inserts. |
| 007 | `clicks.country` stores the ISO 3166-1 alpha-2 code. NULL means unknown, and the API renders NULL as "Unknown". | The world map is keyed by ISO codes. NULL keeps the column honest, and the "Unknown" label is a presentation concern. |
| 008 | Emails are lower-cased by the service layer, with a plain `UNIQUE` constraint. | Case-insensitive uniqueness without a `citext` extension or a functional index. |
| 009 | One error envelope everywhere: `{"error": {"code", "message", "details"}}`. | The frontend can handle every failure path with one code path. |
| 010 | `/api/health` returns 503 only when Postgres is down; Redis down reports `degraded` with 200. | Redirects fall back to Postgres, so the service still works without Redis. |
| 011 | Redis client uses 0.5 s socket and connect timeouts. | A dead Redis must fail fast on the redirect path so the DB fallback is quick instead of hanging. |
| 012 | Migrations run in a one-shot `migrate` compose service; `api` (and later `worker`) wait for it to finish. | Avoids migration races when more than one process starts, and keeps the app image's start command simple. |
| 013 | Redis runs with AOF persistence (`--appendonly yes`). | Click events still waiting in the Redis queue survive a Redis restart. |
| 014 | Uvicorn runs with `--no-proxy-headers`. | The app resolves the client IP from `X-Forwarded-For` itself, trusting only `TRUSTED_PROXIES`, so a single code path owns that security decision. |
| 015 | List-valued settings (`CORS_ORIGINS`, `TRUSTED_PROXIES`) are comma-separated strings. Wildcard CORS is rejected at startup. | Easier to set in hosting dashboards than JSON, and the no-wildcard rule can't be bypassed by config. |
| 016 | Tests use a real Postgres DB (`shortener_test`) and Redis DB 15. The schema is rebuilt via `downgrade base` + `upgrade head` once per run, and every test starts from `TRUNCATE` + `FLUSHDB`. | Exercises the real migrations (both directions). Tests are order-independent without mocking the database. |
| 017 | Local verification on the author's machine used Homebrew **Postgres 15** because Docker was not installed. Compose and CI use **Postgres 16** as specified. | No PG16-only features are used, and CI runs against 16. |
| 018 | Passwords are hashed with **Argon2id** (`argon2-cffi`), passwords are limited to 8–128 chars, and tokens are **PyJWT** HS256. | Argon2id is OWASP's first recommendation (passlib is unmaintained). The length cap bounds hashing cost per request. |
| 019 | Register and login both return `{access_token, token_type, expires_in, user}`. | The frontend is signed in right after registering, without a second round trip. |
| 020 | Login takes JSON, and Swagger uses an `HTTPBearer` scheme instead of the OAuth2 password form. | The API stays JSON-only, and you can still paste a token into Swagger's Authorize dialog. |
| 021 | Unknown email and wrong password return the same 401 body, and an Argon2 verify against a dummy hash equalizes timing. | Prevents account enumeration through the login endpoint. |
| 022 | JWT decoding pins `algorithms=[HS256]`, requires `sub`/`exp`/`iat`, and checks a `type=access` claim. The user must still exist. | Blocks `alg=none` and algorithm-confusion attacks, and makes tokens of deleted users stop working immediately. |
| 023 | `HTTPBearer(auto_error=False)`, so a missing token returns **401** `not_authenticated` instead of FastAPI's default 403. | 401 is the correct status for "no credentials", and the response uses the standard error envelope. |
| 024 | Registration relies on the DB unique constraint (catching `IntegrityError`) rather than a SELECT pre-check. | A pre-check would race under concurrent sign-ups. |
| 025 | Coverage runs with `concurrency = ["thread", "greenlet"]`. | SQLAlchemy's async layer switches greenlets. Without this, coverage under-reports code that runs after DB awaits. |
| 026 | Short codes are 7 random Base62 chars from `secrets`. Collisions are handled by inserting and catching the unique violation on `ix_links_short_code` (identified by SQLSTATE 23505 plus the index name), retrying up to 5 times, then returning 503 `code_generation_failed`. | Race-free and zero-cost in the common case. A SELECT pre-check would race. Matching the index name means unrelated integrity errors are never retried. |
| 027 | Another user's link returns **403** `not_owner`; a nonexistent link returns **404**. Every single-link operation goes through `links_service.get_owned_link`, and list queries filter by `user_id`. | The spec requires 403 for non-owners. Trade-off: 403 reveals that an ID exists, and returning 404 for both would hide it. |
| 028 | Destination URLs are validated in the service layer and the original string is kept, not normalized. Rules: http/https only, a valid host, no embedded `user:pass@`, no whitespace or control chars, at most 2048 chars, and not this service's own host. | Pydantic `HttpUrl` would rewrite the user's URL. Embedded credentials are a phishing trick, and self-links would cause redirect loops. |
| 029 | Link responses include `total_clicks`, computed by a correlated `COUNT(*)` subquery per page row. | The links table needs it. On the `(link_id, clicked_at)` index this is cheap for one page of 20–100 rows. |
| 030 | Search uses `ILIKE` over the URL and short code, with `%`, `_` and `\` escaped and bound as parameters. | Correct literal matching and no SQL injection. A trigram index can be added if search gets slow. |
| 031 | Links are hard-deleted, and clicks go with them via `ON DELETE CASCADE`. | Simple and matches user intent. Deactivating (`is_active=false`) is the reversible option. |
| 032 | Redirect cache entries are JSON at `link:{code}` holding `{id, url, is_active, expires_at, max_clicks, has_password}`. The TTL is 1h, capped at the link's remaining lifetime. | Everything the redirect needs comes from one Redis GET, and an entry never lives far past its expiry. |
| 033 | **Negative caching**: unknown codes are cached as `__missing__` for 60 s, and creating a link invalidates its code's key. | Random-code scans don't each hit Postgres, and a newly created code works immediately. |
| 034 | Deactivated links return **404** and expired links return **410** `link_expired`. Expiry evicts the cache key, and expired or inactive hits are not counted as clicks. | 410 means "permanently gone". Deactivation is reversible and owner-controlled, so it should not reveal that the link exists. |
| 035 | Every Redis call on the redirect path catches errors and degrades: a cache read becomes a miss (Postgres serves the redirect), and a failed cache write or enqueue is logged. A failed invalidation is logged at ERROR, so the entry may be stale for up to its TTL. | Redis is an accelerator, not a dependency of correctness. The stale-on-invalidation-failure window is bounded by the TTL. |
| 036 | Click events in the Redis queue carry the **raw IP** briefly; the worker hashes it before anything reaches Postgres. | The worker needs the raw IP for the GeoLite2 lookup. It is never persisted to the database. |
| 037 | `X-Forwarded-For` is read only when the direct peer is in `TRUSTED_PROXIES`, walking right to left and skipping trusted hops. | Clients can spoof that header, and right-to-left traversal ignores anything they prepend. |
| 038 | Redirect responses send `Cache-Control: private, no-store`. Codes are checked against `^[A-Za-z0-9_-]{3,30}$` before any lookup. | Shared caches won't swallow clicks, and garbage paths are rejected without touching Redis or Postgres. |
| 039 | The `/{short_code}` router is mounted last, and 404/410 on the redirect return the JSON error envelope. | API and docs routes can't be shadowed. A friendly HTML error page can be added later behind the frontend. |
