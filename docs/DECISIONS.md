# Architecture Decision Log

Short ADR-style entries. Each records **what** was decided and **why**, in one or two lines.
Newest entries are appended at the bottom.

| #   | Decision | Reason |
| --- | -------- | ------ |
| 001 | Project name **Linkpulse**. | A short, memorable name for the repo, UI and docs. |
| 002 | Pinned `requirements.txt` / `requirements-dev.txt`; `pyproject.toml` holds tool config only. | Deterministic installs and simple Docker layer caching without requiring Poetry/uv. |
| 003 | SQLAlchemy **2.1.x** (the current 2.x release) using the 2.0-style typed API. | The spec asks for the SQLAlchemy 2.0 API; 2.1 is that same API with fixes. |
| 004 | The full data model (users, links, clicks) ships in the **initial Alembic migration** in Phase 1. | The schema is fully specified up front; one coherent baseline beats three tiny migrations. Every later change is a new migration. |
| 005 | `BIGINT GENERATED BY DEFAULT AS IDENTITY` primary keys, not UUIDs. | Smaller and faster indexes. Ownership is enforced in every query, so guessable IDs leak nothing. |
| 006 | Composite index `clicks(link_id, clicked_at)` replaces a standalone `link_id` index. | Its leftmost prefix serves `link_id` lookups, so a second index would only slow the worker's inserts. |
| 007 | `clicks.country` stores the ISO 3166-1 alpha-2 code. NULL means unknown, and the API renders NULL as "Unknown". | The world map is keyed by ISO codes. NULL keeps the column honest, and the "Unknown" label is a presentation concern. |
| 008 | Emails are lower-cased by the service layer, with a plain `UNIQUE` constraint. | Case-insensitive uniqueness without a `citext` extension or a functional index. |
| 009 | One error envelope everywhere: `{"error": {"code", "message", "details"}}`. | The frontend can handle every failure path with one code path. |
| 010 | `/api/health` returns 503 only when Postgres is down; Redis down reports `degraded` with 200. | Redirects fall back to Postgres, so the service still works without Redis. |
| 011 | Redis client uses 0.5 s socket and connect timeouts. | A dead Redis must fail fast on the redirect path so the DB fallback is quick instead of hanging. |
| 012 | Migrations run in a one-shot `migrate` compose service; `api` (and later `worker`) wait for it to finish. | Avoids migration races when more than one process starts, and keeps the app image's start command simple. |
| 013 | Redis runs with AOF persistence (`--appendonly yes`). | Click events still waiting in the Redis queue survive a Redis restart. |
| 014 | Uvicorn runs with `--no-proxy-headers`. | The app resolves the client IP from `X-Forwarded-For` itself, trusting only `TRUSTED_PROXIES`, so a single code path owns that security decision. |
| 015 | List-valued settings (`CORS_ORIGINS`, `TRUSTED_PROXIES`) are comma-separated strings. Wildcard CORS is rejected at startup. | Easier to set in hosting dashboards than JSON, and the no-wildcard rule can't be bypassed by config. |
| 016 | Tests use a real Postgres DB (`shortener_test`) and Redis DB 15. The schema is rebuilt via `downgrade base` + `upgrade head` once per run, and every test starts from `TRUNCATE` + `FLUSHDB`. | Exercises the real migrations (both directions). Tests are order-independent without mocking the database. |
| 017 | Local verification on the author's machine used Homebrew **Postgres 15** because Docker was not installed. Compose and CI use **Postgres 16** as specified. | No PG16-only features are used, and CI runs against 16. |
| 018 | Passwords are hashed with **Argon2id** (`argon2-cffi`), passwords are limited to 8–128 chars, and tokens are **PyJWT** HS256. | Argon2id is OWASP's first recommendation (passlib is unmaintained). The length cap bounds hashing cost per request. |
| 019 | Register and login both return `{access_token, token_type, expires_in, user}`. | The frontend is signed in right after registering, without a second round trip. |
| 020 | Login takes JSON, and Swagger uses an `HTTPBearer` scheme instead of the OAuth2 password form. | The API stays JSON-only, and you can still paste a token into Swagger's Authorize dialog. |
| 021 | Unknown email and wrong password return the same 401 body, and an Argon2 verify against a dummy hash equalizes timing. | Prevents account enumeration through the login endpoint. |
| 022 | JWT decoding pins `algorithms=[HS256]`, requires `sub`/`exp`/`iat`, and checks a `type=access` claim. The user must still exist. | Blocks `alg=none` and algorithm-confusion attacks, and makes tokens of deleted users stop working immediately. |
| 023 | `HTTPBearer(auto_error=False)`, so a missing token returns **401** `not_authenticated` instead of FastAPI's default 403. | 401 is the correct status for "no credentials", and the response uses the standard error envelope. |
| 024 | Registration relies on the DB unique constraint (catching `IntegrityError`) rather than a SELECT pre-check. | A pre-check would race under concurrent sign-ups. |
| 025 | Coverage runs with `concurrency = ["thread", "greenlet"]`. | SQLAlchemy's async layer switches greenlets. Without this, coverage under-reports code that runs after DB awaits. |
| 026 | Short codes are 7 random Base62 chars from `secrets`. Collisions are handled by inserting and catching the unique violation on `ix_links_short_code` (identified by SQLSTATE 23505 plus the index name), retrying up to 5 times, then returning 503 `code_generation_failed`. | Race-free and zero-cost in the common case. A SELECT pre-check would race. Matching the index name means unrelated integrity errors are never retried. |
| 027 | Another user's link returns **403** `not_owner`; a nonexistent link returns **404**. Every single-link operation goes through `links_service.get_owned_link`, and list queries filter by `user_id`. | The spec requires 403 for non-owners. Trade-off: 403 reveals that an ID exists, and returning 404 for both would hide it. |
| 028 | Destination URLs are validated in the service layer and the original string is kept, not normalized. Rules: http/https only, a valid host, no embedded `user:pass@`, no whitespace or control chars, at most 2048 chars, and not this service's own host. | Pydantic `HttpUrl` would rewrite the user's URL. Embedded credentials are a phishing trick, and self-links would cause redirect loops. |
| 029 | Link responses include `total_clicks`, computed by a correlated `COUNT(*)` subquery per page row. | The links table needs it. On the `(link_id, clicked_at)` index this is cheap for one page of 20–100 rows. |
| 030 | Search uses `ILIKE` over the URL and short code, with `%`, `_` and `\` escaped and bound as parameters. | Correct literal matching and no SQL injection. A trigram index can be added if search gets slow. |
| 031 | Links are hard-deleted, and clicks go with them via `ON DELETE CASCADE`. | Simple and matches user intent. Deactivating (`is_active=false`) is the reversible option. |
| 032 | Redirect cache entries are JSON at `link:{code}` holding `{id, url, is_active, expires_at, max_clicks, has_password}`. The TTL is 1h, capped at the link's remaining lifetime. | Everything the redirect needs comes from one Redis GET, and an entry never lives far past its expiry. |
| 033 | **Negative caching**: unknown codes are cached as `__missing__` for 60 s, and creating a link invalidates its code's key. | Random-code scans don't each hit Postgres, and a newly created code works immediately. |
| 034 | Deactivated links return **404** and expired links return **410** `link_expired`. Expiry evicts the cache key, and expired or inactive hits are not counted as clicks. | 410 means "permanently gone". Deactivation is reversible and owner-controlled, so it should not reveal that the link exists. |
| 035 | Every Redis call on the redirect path catches errors and degrades: a cache read becomes a miss (Postgres serves the redirect), and a failed cache write or enqueue is logged. A failed invalidation is logged at ERROR, so the entry may be stale for up to its TTL. | Redis is an accelerator, not a dependency of correctness. The stale-on-invalidation-failure window is bounded by the TTL. |
| 036 | Click events in the Redis queue carry the **raw IP** briefly; the worker hashes it before anything reaches Postgres. | The worker needs the raw IP for the GeoLite2 lookup. It is never persisted to the database. |
| 037 | `X-Forwarded-For` is read only when the direct peer is in `TRUSTED_PROXIES`, walking right to left and skipping trusted hops. | Clients can spoof that header, and right-to-left traversal ignores anything they prepend. |
| 038 | Redirect responses send `Cache-Control: private, no-store`. Codes are checked against `^[A-Za-z0-9_-]{3,30}$` before any lookup. | Shared caches won't swallow clicks, and garbage paths are rejected without touching Redis or Postgres. |
| 039 | The `/{short_code}` router is mounted last, and 404/410 on the redirect return the JSON error envelope. | API and docs routes can't be shadowed. A friendly HTML error page can be added later behind the frontend. |
| 040 | Reliable queue: the worker moves events from `clicks:queue` into its own `clicks:queue:processing:{WORKER_ID}` list (BLMOVE for the first event, then a Lua script for the rest of the batch). It clears that list only after the DB commit, and any unfinished batch is retried first. | A worker crash or DB outage never loses events. Each event always lives in exactly one Redis list. |
| 041 | `clicks.event_id` (UUID, unique) is added in a second migration. Inserts use `ON CONFLICT (event_id) DO NOTHING`. | Gives effectively exactly-once storage: a crash between commit and ack can't double-count when the batch is retried. |
| 042 | One multi-row `INSERT ... VALUES` per batch (≤100 rows). Events whose link was deleted in the meantime are filtered out first, and malformed events go to `clicks:queue:dead`. | One round trip per batch. One bad event can't block the queue forever, and dead letters can be inspected. |
| 043 | When Redis is down at redirect time, the API writes the click itself in a `BackgroundTask` after the 302 has been sent. | Clicks aren't lost when Redis is down, and the user doesn't wait for the DB write. |
| 044 | The IP hash is HMAC-SHA256 keyed by `IP_HASH_SALT`, a salted SHA-256 construction. | HMAC is the standard keyed-hash construction. The salt is a secret because the IPv4 space is small enough to brute-force otherwise. |
| 045 | Referrers are stored as a normalized host (`news.ycombinator.com`, `www.` stripped), with NULL meaning direct traffic. | Hosts aggregate cleanly for the chart, and full referrer URLs can contain tokens or personal data. |
| 046 | UA → `browser`/`os` family plus `device_type` ∈ {mobile, tablet, desktop, bot, other}. Unrecognized values become "Unknown". Parse results are LRU-cached. | Stable, low-cardinality chart buckets. Real traffic repeats a small set of UA strings. |
| 047 | Geo uses GeoLite2 through a lazily opened, memory-mapped reader. A missing or corrupt file, or a private, loopback or invalid IP, gives Unknown. The `.mmdb` is mounted into containers, never committed or baked into the image. | MaxMind's license forbids redistribution, and the system must work without the file. |
| 048 | The worker has its own Redis client with a 6 s socket timeout, longer than the 1 s BLMOVE block, and handles SIGTERM by finishing the current batch. Compose gives it a 30 s stop grace period. | The API client's 0.5 s timeout would break blocking reads. Graceful shutdown means deploys don't leave half-processed batches. |
| 049 | The stats range is inclusive local calendar days (`from`/`to` as `YYYY-MM-DD`), defaulting to the last 30 days. An optional IANA `tz` (default UTC) defines day boundaries, and ranges are capped at 366 days. | The dashboard's 7d/30d/90d selectors map directly onto it. A viewer in India sees their own days, not UTC days. The cap bounds query cost. |
| 050 | The window converts to exact UTC instants (`clicked_at >= start AND < end_exclusive`) before querying. | Half-open, sargable bounds use the `(link_id, clicked_at)` index, which EXPLAIN confirms as an index condition. Wrapping `clicked_at` in a function would prevent that. |
| 051 | Zero-filling happens in SQL: `generate_series(from, to, 1 day)` LEFT JOINed to per-day `GROUP BY` counts. | The spec asks for SQL aggregation, and the API always returns exactly one point per day. |
| 052 | Unique visitors = `COUNT(DISTINCT ip_hash)` over the window, and per day for the timeseries. | Simple and exact at this scale. HyperLogLog is a future option at very high volume. |
| 053 | Breakdowns are top-10 per dimension, ordered by count descending then label. NULL referrer is labeled "Direct", and NULL or unknown values are labeled "Unknown". | Deterministic ordering makes stable charts and tests. Labels are a presentation concern, so storage stays NULL. |
| 054 | Stats are cached at `stats:{link}:{from}:{to}:{tz}` for 60 s. The ownership check always queries Postgres first, and a Redis failure just skips the cache. | The cache can never leak another user's data or a deleted link. 60 s staleness is acceptable for analytics. |
| 055 | The frontend is scaffolded from Vite's official `react-ts` template (Vite 8, TypeScript 6, oxlint), with React Router 7 and Tailwind 4 via `@tailwindcss/vite`. | Starting from the template keeps tool versions mutually compatible. oxlint ships with the template and is fast. |
| 056 | The JWT is kept in `localStorage` and sent as a Bearer header. CORS is an explicit allow-list with credentials off. | Simple and stateless, with no CSRF surface. Trade-off: readable by XSS, mitigated by React's escaping and no `dangerouslySetInnerHTML`. An httpOnly cookie plus CSRF token is the hardening path. |
| 057 | Chart colors use the validated reference data-viz palette as CSS tokens, with separately stepped dark-mode values. Categorical slots are fixed-order, donuts cap at 5 slices plus a gray "Other", the map uses one sequential blue hue, and referrer bars use a single hue. | The palette passes the colorblind-separation checks (validator run). Fixed order means a browser keeps its color between ranges. Ramps on nominal categories would mislead. |
| 058 | Every chart card has a table-view toggle. Donut legends show labels and shares, and tooltips enhance but never gate a value. | Light-mode yellow, aqua and magenta sit below 3:1 contrast, so values must be readable without color or hover. |
| 059 | TanStack Query `keepPreviousData` dims the previous render while a new range or page loads (no skeleton flash). Stats refetch every 30 s. Skeletons appear only on first load. | No layout jump between 7d/30d/90d, and the dashboard stays fresh without a reload. |
| 060 | Day ranges are computed in the browser's timezone and sent as `tz`. | A viewer sees "today" as their own today. |
| 061 | The world map is lazy-loaded (its own chunk), and country names come from `Intl.DisplayNames`. `i18n-iso-countries` is used only for the alpha-2 → numeric mapping that world-atlas ids need. | Keeps the initial bundle smaller, and short browser-native names ("United States") fit the KPI cards. |
| 062 | The seed script (`python -m scripts.seed`) uses a fixed RNG seed. It deletes only the demo user's own data and refuses to run if a demo short code belongs to another account. | Reproducible screenshots, and it can't clobber real users' links on a shared database. |
| 063 | The frontend container is a multi-stage build to nginx with SPA fallback and immutable caching for hashed assets. `VITE_API_BASE_URL` is a build arg, and `vercel.json` adds the same SPA rewrite for Vercel. | Vite inlines env vars at build time, so the API URL must be known when building. |
| 064 | Custom aliases match `^[a-zA-Z0-9_-]{3,30}$`, are case-sensitive like generated codes, and are checked against a reserved-word list case-insensitively (`api`, `login`, `admin`, `docs`, …). A taken alias returns 409 `alias_taken` from the unique index, with no retry. | One code namespace for aliases and random codes. The blocklist protects app routes and blocks impersonation-style aliases like "Admin". |
| 065 | `max_clicks` is enforced by a Redis counter (`clicks:used:{link}`) that is checked and incremented atomically in Lua. A missing key is rebuilt from the human clicks in Postgres, and when Redis is down the Postgres count is used. | The clicks table lags behind the async worker, so it can't gate in real time. Lua makes check-and-increment race-free across API replicas. |
| 066 | A cheap precompiled regex (`utils/bots.py`) flags crawlers, link unfurlers (Slack, WhatsApp, Discord, …) and HTTP libraries on the redirect path, and an empty UA counts as a bot. Bots are redirected but never consume `max_clicks`. | Pasting a single-use link into Slack shouldn't burn it. A regex is microseconds, unlike full UA parsing, which stays in the worker. |
| 067 | `expires_at` must be timezone-aware and in the future. In PATCH, an explicit `null` clears `expires_at`/`max_clicks` and an omitted field is left unchanged (`model_fields_set`). | Avoids silently interpreting naive timestamps, and gives standard JSON-merge-patch-like semantics. |
| 068 | Link responses include a computed `status` (`active`, `paused`, `expired`, `limit_reached`). `total_clicks` and `status` count human clicks only. | The UI shows one clear badge, and the counts match what `max_clicks` enforces. |
| 069 | QR codes come from `segno`, which is pure Python and renders PNG and SVG without Pillow: `GET /api/links/{id}/qr?format=png|svg&scale=&download=`. Owner only, error-correction level M, and `Cache-Control: private`. | No native imaging dependency in the image. SVG scales cleanly for print, and level M balances density against damage tolerance. |
| 070 | Password-protected links: `GET /{code}` serves a self-contained server-rendered HTML form (strict CSP, `frame-ancestors 'none'`, no JS, destination never shown), and `POST /{code}` verifies the Argon2 hash and answers **303**. Hashes are read from Postgres and never cached in Redis. A click is counted only after a successful unlock. | Works without the SPA. 303 is the correct POST → GET redirect. Keeping hashes out of the cache limits what a Redis leak exposes. |
| 071 | The one-field unlock form is parsed with `urllib.parse.parse_qs` from a size-capped body, instead of adding `python-multipart`. | One less dependency for a single field. |
| 072 | A hand-written **sliding-window-counter** rate limiter runs as one Lua script per request (check + INCR + PEXPIRE). Its keys share a `{hash tag}` so they land in one cluster slot, and the clock is the app's NTP-synced clock. | O(1) memory per client, no boundary double-burst (unlike a fixed window), atomic across replicas, one round trip. Clock skew of a few ms doesn't matter for 60 s windows. |
| 073 | Limits: login 10/min/IP, register 5/h/IP, create link 30/min/user, redirect 300/min/IP, password unlock 5/min per IP per link. Responses are 429 `rate_limited` with `Retry-After`, and allowed requests carry `RateLimit-Limit/Remaining` headers. | Stops credential stuffing, signup spam and password brute force without affecting normal use. |
| 074 | The limiter **fails open** when Redis is down, and `RATE_LIMIT_ENABLED=false` turns it off (used for load tests). | Availability over strictness: a Redis outage shouldn't lock every user out. A benchmark from one machine would otherwise be throttled as a single IP. |
| 075 | Unique vs total clicks was already covered by Phase 6 (`unique_visitors` overall and per day, shown in the dashboard), so no extra work was needed in Phase 8. | Avoids duplicating an existing feature. |
| 076 | Bot filtering: the worker marks `device_type='bot'` when either the `user-agents` parser or the shared bot regex matches, and a missing UA counts as a bot. Stats exclude bots by default, return `bot_clicks`, and accept `include_bots=true`, which is part of the cache key. The breakdown uses Postgres `COUNT(*) FILTER (WHERE …)` in one pass. | Link unfurlers and crawlers would otherwise inflate clicks, especially right after a link is shared. Bots are still stored, so the filter is reversible and auditable. |
| 077 | Google Safe Browsing v4 Lookup checks new and edited destination URLs (422 `unsafe_url` with the threat types). It's optional (skipped without `SAFE_BROWSING_API_KEY`), uses a 2 s timeout and **fails open**, and the checker is a FastAPI dependency behind a `Protocol`. | Shorteners are a favorite phishing tool. Failing open keeps a third-party outage from breaking link creation, and DI keeps tests offline and deterministic. |
| 078 | `httpx` moved from dev to runtime dependencies. | The Safe Browsing client uses it, and it was already the test client. |
